我收藏的这篇长帖有近两百个楼层，原作者是一名人工智能方向的在读博士生。它最值得留下的不是某个模型排名，而是把 AI 放进日常入口、科研阅读、代码代理和定期复盘里，最后又提醒读者警惕“效率幻觉”。

这篇文章不是把原帖改写成“我的博士经历”。我只取其中能被验证、能被复用的结构，并把原作者的具体体验和我自己的判断分开。产品名称和模型能力会变化，工作流的边界反而更值得保留。

## 我从原帖里保留的四个动作

| 动作         | 原帖里的具体例子                                 | 我保留它的原因                                 |
| ------------ | ------------------------------------------------ | ---------------------------------------------- |
| 降低入口摩擦 | 豆包划词工具、通过 IM 远程派活给 Agent           | 让“先问一下”变成低成本动作，而不是打开一堆网页 |
| 先澄清再执行 | 四个模型分别复述需求、继续追问、画 ASCII 原型    | 把隐含决策提前暴露，减少做完才发现方向错了     |
| 按任务分角色 | 宏观调研、逐句精读、代码实现和审稿由不同环节承担 | 不把“会聊天”误当成所有任务都适合的能力         |
| 定期做减法   | 关闭重复的 Skill / MCP，比较装上前后的真实增量   | 工具越多不一定越强，选择成本也会进入上下文     |

原帖还提到用 Agent 读日记、提醒作息、整理知识库。这类例子说明了“入口贴近日常”的想象力，但涉及隐私和长期授权，我不会把它直接当成普适建议。

## 一个复杂需求是怎样被拆开的

原帖给出的复杂需求流程很具体：先把同一个模糊需求同时发给多个模型，让它们用自己的话复述并提问；人逐个回答；再要求模型输出 ASCII 原型，直到关键问题都暴露出来；最后才交给执行能力更强的 Agent。

我把它改写成下面这张“协作合同”：

```text
输入：目标、已有材料、不能改变的约束
第一轮：多个模型只做复述和追问，不写代码
第二轮：合并问题，画出状态、页面或数据流的草图
人工确认：删掉不必要的范围，写清验收标准
执行：一次只改一个小块，每步保留验证结果
交接：留下变更摘要、未决问题和回滚入口
```

这套流程的价值不在于“同时开四个模型”本身。如果需求很小，多模型只会增加整理成本；只有当一句话背后确实藏着多个决策点时，先让模型互相暴露盲区才值得。

## 科研部分：从入口到证据，而不是工具清单

原帖把科研文献阅读拆成“调研 → 文献网络分析 → 精读 → 知识整合”。调研阶段要求同时覆盖最新工作和领域早期代表作；找到锚点后，再用引用关系判断技术脉络；精读时把宏观分析和逐句解释分开；最后把个人理解与图示交叉验证。

我认为这里最重要的不是原帖提到的某个产品，而是两个检查点：

- 模型给出的作者、年份、DOI 和引用关系必须回到数据库或原文核对。
- AI 生成的科研图只能先当草图，涉及数据、坐标和因果关系的部分要人工逐项检查。

同样的原则也适用于写作。可以让模型分别扮演结构审阅者、复现实验者和普通读者，但不能把“读起来顺”当成论断正确。原帖作者自己也强调，模型一旦理解错了，后续会越写越长、越写越偏。

## “效率幻觉”是这篇长帖最值得摘出来的段落

原帖对效率幻觉的描述很具体：代码看起来一直在生成，自己却慢慢说不清楚到底改了什么，甚至忘了当初为什么这样设计。AI 把执行成本压低以后，人更容易在问题还没想清楚时就开始做，最后得到的是流畅的偏航。

我给自己留了两个判断问题：

1. 我还能不能用自己的话说清楚问题和验收标准？
2. 如果模型停下来，我能不能指出下一步要验证的事实，而不是只催它继续？

如果两个答案都是“不能”，我会先停掉执行，自己写一版问题定义。这里最有效的动作通常不是再加一段更强硬的提示词，而是重新确认目标、范围和证据。

## Skill 不是收藏夹，需要做一次对照实验

原帖提到的 Skill / MCP 堆积问题，我在整理资料时也很有共鸣：同类工具的描述相似，模型有时选 A，有时选 B，输出变慢却很难说是哪一个带来了收益。

现在我会给新工具设一个最小评测：

| 对照组       | 要记录什么                             |
| ------------ | -------------------------------------- |
| 不使用 Skill | 完成同一任务的时间、返工轮数和错误类型 |
| 使用 Skill   | 是否减少了步骤，是否新增上下文噪声     |
| 连续三次任务 | 模型是否稳定选择，结果是否可重复       |

如果只在一次演示里看起来惊艳，却不能减少后续返工，我倾向于关闭它。Skill 的描述也要写清输入、输出和不适用场景，否则它只是另一个需要模型猜测的菜单项。

## 我不会直接照搬的部分

- 不会把原帖中的模型排名当成长期结论；模型、价格、地区和产品策略都在变。
- 不会把“给日记权限”当作普通效率技巧，任何长期读取都要先做数据范围和撤销设计。
- 不会为了让模型继续发散而使用带压迫感的提示，先检查需求是否已经足够清楚。
- 不会把 AI 生成的图片、论文审稿意见或代码原样发布，最终责任仍然在我。

## 我的版本：AI 是放大器，主变量仍是人

这篇长帖让我留下的工作流很短：让 AI 更容易被调用，让它在开始执行前多问几句，把不同任务拆给不同角色，最后定期删除没有增量的工具。真正不能外包的是问题表述、必要取舍和验收标准。
