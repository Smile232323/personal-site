这篇帖有近两百个楼层，标题里就写着“在读博士生如何与 AI 协作”。我真正记住的却不是模型名，而是开头那句“当同事，不当工具”，以及后面一串很具体的入口：划词工具栏、通过 IM 给远端 Agent 派活、让不同模型分别复述需求、把稳定流程沉淀成 Skill。

原帖作者把这些东西放在日常、科研、Code Agent 和定期复盘里讲。整理成博客时，我刻意没有把他的博士经历写成我的故事，只记“哪些动作可以复查，哪些体验只能归还给原帖”。

## 先把 AI 放到真的会经过的地方

原帖举的第一个例子很普通：在电脑上划词，直接做概念解释、翻译或搜索；更进一步，用 IM 把任务扔给远端工作台，让 Agent 去下载、转写、分析、跑代码或生成 PDF。配图里也有一张很直白的流程图，把划词、IM 派活、远程工作台和个人知识库画成环。

这类入口的判断标准不是“功能多不多”，而是从看到问题到发出第一句请求要不要跨好几个窗口。入口近，才会真的被用起来。入口一旦接触到日记、项目文件或长期对话，另一套问题也会跟着来：读了哪些数据，谁能撤销，任务失败时怎样清掉上下文。原帖提到的生活提醒和日记读取，我只把它当成权限设计的例子，没有把它包装成普通效率技巧。

## 复杂需求，先让模型把误解说出来

原帖给了一个我很愿意保留的顺序：把模糊需求同时交给几个模型，让它们先复述、提问，不急着写代码；人把问题逐个回答后，再让模型画 ASCII 原型或数据流草图；范围和验收标准确认了，才交给执行能力更强的 Agent。

我把这段顺序压成一张协作单：

```text
输入：目标、已有材料、不能改变的约束
第一轮：只复述和追问，不写实现
第二轮：画页面、状态或数据流草图
人工确认：删掉不必要的范围，写出验收标准
执行：一次只改一个小块，每一步都留下验证结果
交接：记录变更、未决问题和回滚入口
```

多模型不是默认配置。改一个小按钮时，四份复述只会增加整理成本；需求背后藏着页面、状态、数据和权限等多个决策时，先让模型互相暴露盲区才划算。

## 科研部分让我更在意“证据链”

原帖把文献工作拆成“课题调研 → 文献网络分析 → 精读 → 知识整合”。截图里能看到一份关于 Darwin Gödel Machine 的深度解析页面、一张引用关系网络图，以及一套从宏观报告到逐句解释的阅读界面。它们看起来很完整，但完整的页面不等于正确的论文结论。

我留下两个硬检查：作者、年份、DOI 和引用关系要回到数据库或原文核对；AI 生成的科研图先当草图，数据、坐标、因果方向和图注再逐项对照。模型可以把一篇论文整理得很顺，顺不代表没有漏掉限定条件。

## Code Agent 的重点是交接，而不是一直生成

原帖把复杂需求画成一个更长的协作过程，也谈到不同模型在调研、代码实现、审阅上的分工。对我而言，最实用的不是记住“哪个模型适合什么”，而是给每个阶段留下能交接的东西：问题定义、已有上下文、这一步改了什么、怎样验证、还有什么没解决。

如果一段代码只能靠连续对话维持，一旦换模型或中断，工作就会重新开始。相反，一个小任务只要有明确输入、输出和验证方式，就算执行者换了，也能继续往下走。

## “效率幻觉”不是抽象警告

原帖后半段讲到一种很具体的失控：代码一直在生成，自己却越来越说不清改了什么，甚至忘了最初为什么这样设计。执行成本下降以后，人很容易在问题尚未想清楚时就开工，最后得到一条流畅但偏离目标的路径。

我会在继续让 Agent 工作前问两句：

1. 我能不能用自己的话说清目标和验收标准？
2. 如果它现在停下来，我能不能指出下一条要核对的事实？

答不上来时，应该停执行、重写问题定义，而不是再加一段更强硬的提示词。这里的“停”不是反 AI，而是把主变量拿回手里。

## Skill 要靠对照实验留下来

原帖提到 Skill 和 MCP 越堆越多后，模型会在相似工具之间摇摆，输出变慢，却很难说清收益来自哪里。整理这篇帖时，我给新工具留了一个很小的对照：

| 情况         | 记录                             |
| ------------ | -------------------------------- |
| 不使用 Skill | 时间、返工轮数、错误类型         |
| 使用 Skill   | 是否少了步骤，是否增加上下文噪声 |
| 连续三次任务 | 模型是否稳定选择，结果能否复现   |

一次演示里很惊艳、连续三次却没有减少返工的工具，我会先关掉。Skill 的说明也要写输入、输出和不适用场景，否则它只是另一个要模型猜的菜单。

## 我不会从原帖直接搬走的部分

- 不把原帖里的模型排名写成长期结论；价格、地区和产品策略会变。
- 不把日记、项目文件的长期权限当成普通效率开关；先做范围、保留期和撤销设计。
- 不把 AI 生成的论文意见、图片或代码原样公开；先做事实、隐私和版权复核。
- 不把“用了 AI”当成交付标准；最终还要能说明结果怎样验证、哪里可能错。

这篇长帖让我留下的顺序很短：入口要近，需求要先说清，任务要能交接，工具要定期做减法。模型可以替我压低执行成本，但问题表述、取舍和验收仍然需要有人负责。
