这篇 AI 协作长帖的第 104 楼，问了一个我很想继续追的问题：AI 已经帮忙检索、筛选和汇总，但输出没有很好的原文对照，怎么知道它是否全面、是否过时、是否可靠？

楼主回复自己使用检索工具时体验不错。提问者又在 [#110 楼](https://linux.do/t/topic/2059718/110) 解释，他不是只想搜到更多内容，而是想把生成的回答和信源对应起来。这个区别很重要。十页流畅的报告，和十条能回到论文检查的笔记，读起来可能都像完成了工作，后面却不一样。

原帖作者是一名 AI 方向的在读博士生，分享了日常工具、文献阅读、写作和 Code Agent 协作。这次我沿着“一个问题怎样被解释、留下、再核对”这条线重排，保留他的做法，也把评论里没有完全解决的地方留下来。

## 划词入口很近，解释也要带一点上下文

作者日常使用豆包的划词工具栏，自定义了一个“概念解释器”。阅读时选中术语就能解释，省掉复制、打开搜索页、再描述问题的几个动作。

![原帖概念解释器示例，围绕划词工具栏给出引言、定义和使用场景，并列出被引用文档](/personal-site/media/posts/ai-collaboration-04.jpeg)

_来源：[原帖 #1 楼](https://linux.do/t/topic/2059718/1)。这是作者展示的划词解释界面。_

这样的入口适合先把阅读继续下去，不必每碰到一个词都打断半分钟。但同一个词放在不同句子里可能有不同作用。只划词，模型给的是常见解释；把所在段落也交出来，才更容易问清这里具体指什么。

比如论文里的 “sample”，可能是在说一个样本，也可能是在说一次采样动作。查词结果通顺，不代表这句话已经翻译对。遇到影响公式、方法或实验设置的词，我会把整句和前后文留进笔记，继续问它怎样与论文里的符号对应。

评论 [#109 楼](https://linux.do/t/topic/2059718/109) 提供了另一个实际限制：有人照着用了两天，觉得满足需求，可五六年前的笔记本运行起来太重。作者够用的入口，对另一台电脑未必轻便。试用时看它是否减少打断，也看启动和驻留是否带来新的负担。

## 远程派活，最好带着能定位的材料

![原帖低摩擦入口说明图，连接划词工具栏、IM 派活、远程工作台和个人知识库](/personal-site/media/posts/ai-collaboration-02.jpeg)

_来源：[原帖 #1 楼](https://linux.do/t/topic/2059718/1)。这是原作者用来解释工作流的示意图，不是实际任务运行日志。_

主帖谈到通过 IM 把任务交给远程 Agent，让工作台完成下载、转写、分析、运行代码和生成文件。这些动作的便利在于，不必一直坐在电脑前盯着同一个窗口。

不过，“分析刚才那篇论文”很依赖对话记忆。换会话或换设备以后，那个“刚才”可能已经没有对象。我更愿意在请求里带上论文题名或文件位置、这次只看哪一部分，以及希望收到什么。比如先要三条方法限制，每条附原文位置，不急着要完整周报。

这样返回结果后才能继续问：“第二条对应哪一页？”如果资料访问失败，也应单独显示，而不是在报告里用常识补齐缺掉的部分。未取得全文时，结论就只按拿到的摘要或片段处理。

## 引用网络可以决定先读什么，不能决定什么已经被证明

作者把文献阅读分为调研、筛选、精读和整合。调研时既找新论文，也找开山之作；有了几篇锚点后，再看引用网络，寻找关联工作。

![原帖的 Darwin Gödel Machine 文献网络页面，左侧列出相关论文，中央显示节点，右侧为所选论文摘要](/personal-site/media/posts/ai-collaboration-03.jpeg)

_来源：[原帖 #1 楼](https://linux.do/t/topic/2059718/1)。引用数量与页面内容是当时的界面快照。_

这张图把“下一篇可以点哪里”展示得很直观。先看一个锚点的前作，再看后续工作如何回应它，容易形成阅读顺序。相邻论文却未必支持相同观点；相似题名可能采用不同实验设定，图中的一条联系也不能直接写成某个因果结论。

原帖用网络规模判断方向是否拥挤，我会把它保留成一种初筛直觉，而不是确定的“蓝海”指标。网络大小还与检索范围、论文年龄和工具收录有关。真正要判断自己的研究空间，仍要读清已经解决了什么、用什么条件解决、还有什么没覆盖。

笔记里可以只留一组具体关系：本文沿用了哪篇的方法，改变了哪个设置，与哪个基线比较。能答这几个问题，图就不只是漂亮的节点集合。

## 漂亮的宏观报告，拿来提问更有用

作者精读时用两个模型配合：一个先从动机、建模、实验、结论和评述组织宏观视角，另一个处理关键句与细节。下面是他展示的报告页面。

![原帖用模型生成的 Darwin Gödel Machine 解析页面，按动机、建模、实验、结论与评述分栏展示](/personal-site/media/posts/ai-collaboration-01.jpeg)

_来源：[原帖 #1 楼](https://linux.do/t/topic/2059718/1)。这是模型生成的阅读报告，不是论文原文或经过核验的发表记录。_

报告左侧声称涵盖论文“90% 以上的核心价值”，但截图没有给出这个比例如何计算。读者更容易实际核对的是一两个具体问题：它引用的实验在什么数据上做，比较对象是谁，限制条件有没有被省掉。页面标签和实验数字也应回到 PDF 查。

我会把宏观报告当成目录来用。比如它列了一个采样策略，就追问公式在哪里、每个符号如何定义；它说某项实验改善明显，就去看表格的设置和对照。报告负责指路，精读负责让这些解释落到具体段落。

可以给模型一个很短的要求：

```text
只基于这份 PDF 解释这个问题。
把原文位置、原文说了什么、你的解释分开写。
原文没有交代的部分标为“未说明”，不要替作者补结论。
```

这段是整理时补充的问法，不是原帖附带的 Skill。模型写了页码，也还要实际打开那个位置看；如果问题关系到图表，不能只检查正文的一句摘要。

评论 [#131 楼](https://linux.do/t/topic/2059718/131) 推荐了 [clibib](https://github.com/delip/clibib)，从 URL、arXiv ID、PubMed ID 或 DOI 获取 BibTeX 条目。它是减少手工拼错引用信息的入口，但书目信息对了，仍不代表正文对这篇论文的概括正确。两个检查应分开。

## 换模型以前，先留下读过什么

原帖说读完后把讨论整合进 wiki，必要时再生成一张信息图。这个顺序值得保留：图应当整理已有理解，而不是用一张看似完整的图替代阅读。

每篇论文的记录不必很长。留住原始文件、三个重要结论与位置、一个没有搞懂的问题，以及哪些解释已经对照过原文。下次换模型，先把这份记录交过去，再指定只处理未决问题，不需要让它重新总结整篇。

交给 Code Agent 时也一样。评论 [#163 楼](https://linux.do/t/topic/2059718/163) 问，自己不太懂代码，该如何判断 AI 生成的代码可信：自己看、让另一个模型审，还是结果对了就行？保存的讨论没有给出一套能替代专业审阅的保证。一个小例子跑通可以说明这个例子可用，不能覆盖其他输入。至少要留下输入、预期结果、实际输出和运行方式，后续才有人能继续检查。

原帖还提到工具堆多了，模型会在几个相似 Skill 之间不稳定地选择。读论文也是如此：如果每次同一个问题都被引向不同流程，先保留最常用的一条，把输入和输出说清，通常比再找一套“全自动科研”更容易积累笔记。

下次读一篇论文，可以拿四件小事验收：重要结论能否定位到原文；引用元数据是否对应；没有读懂的地方是否仍清楚地列着；换一个会话后能否接着那个问题继续。做完这些，摘要才真的接回了自己的阅读过程。
