这份科研汇总帖里，我最想留下的一组对话发生在第 195 到 198 楼。

有人推荐 Edit Banana，说在线版能用，却在本地复现不出同样的效果。另一位贴了一张项目说明，指出开源版本落后于网页服务。前一个人接着说，想自己改，但暂时没有做计算机视觉的经验。

这比“科研神器合集”具体多了。同一个名字，网页和仓库可能不是同一套功能；能打开演示，和能在自己的环境里继续修改，也不是同一步。收藏时若没有记下这件事，等真正要改论文图，还是会重新踩一次坑。

原帖从 2026 年 1 月开始维护，保存的主帖已经列到了文献阅读、写作、绘图、汇报、审稿和求职。这里不把整份目录照搬，只挑几条能接上实际工作的入口，再把评论里的补充放到旁边。

## 正在找文献时，先打开哪几个入口

主帖的“文献阅读与写作”和“常用工具与工作流”很长，检索教程、阅读工具、综述写作和排版混在两组目录里。下面这几项可以按眼前缺的东西来选：

| 眼前的问题                         | 原帖列出的入口                                                          |
| ---------------------------------- | ----------------------------------------------------------------------- |
| 不知道怎样跟踪一个方向             | [快速检索文献的讨论](https://linux.do/t/topic/1407068)                  |
| PDF 已经找到，想辅助阅读           | [Zotero-AI-Butler](https://linux.do/t/topic/1415975)                    |
| 引用条目要逐个核对                 | [citation-checker](https://github.com/QAbot-zh/citation-checker)        |
| 想把 Zotero 文献接入 Markdown 写作 | [Zotero + Obsidian 写论文](https://linux.do/t/topic/1771234)            |
| 草稿已有，想看写作经验             | [Paper Writing Tips](https://github.com/MLNLP-World/Paper-Writing-Tips) |
| 不确定研究过程怎么安排             | [彭思达的科研经验](https://github.com/pengsida/learning_research)       |

它们都来自原帖目录，不是一套必须全部安装的工具组合。我没有在这次整理中跑完这些项目。比如“PDF 已经找到”和“还在判断该读哪篇”，需要的入口就不同；没必要为了找三篇论文先搭一个写作平台。

找到论文后，最好留下题名、作者、年份、DOI 或原始地址，再记一句为什么与当前问题有关。AI 给出的相关性解释可以帮助筛选，但那句话不能代替原文。引用核验工具也主要处理条目有没有错，不会自动证明某篇论文支持你要写的论断。

这份目录里的 [文献 RSS 订阅讨论](https://linux.do/t/topic/1419098) 还提供了另一个方向：与其每天重新搜一遍同样的关键词，可以把已经确认有用的来源固定下来。但第一轮关键词太宽时，订阅只会稳定地带来更多噪声，先手动看一小批结果更容易知道该收窄什么。

## 论文图好看之后，还能不能改

[#192 楼](https://linux.do/t/topic/1417107/192) 推荐了 PaperBanana 和 AutoFigure-Edit，并引用了下面的比较图。

![科研汇总帖回复引用的插图比较，三行分别标为 Human、Nano-Banana-Pro 和 Paper-Banana，展示两类论文框架图](/personal-site/media/posts/research-library-01.jpeg)

_来源：[原帖 #192 楼](https://linux.do/t/topic/1417107/192) 引用的资料图片。画面是插图样例比较，不是本次整理做出的测试。_

图里最容易注意到的是配色和布局，但真正改稿时，还会遇到更小的需求：删一个模块、改一根箭头、把某个术语与正文统一。若输出是一张位图，局部返工可能要重新生成整张图；若元素可编辑，至少有机会只调整对应部分。

因此我会把两个入口分开记：[PaperBanana](https://github.com/dwzhu-pku/PaperBanana) 是原帖推荐的自动插图方向；[AutoFigure-Edit](https://github.com/TuchuanLin/AutoFigure-Edit) 在被引用的介绍中强调可编辑矢量图。这里的“可编辑”是项目介绍中的主张，具体能保留多少元素、输出什么格式，要用自己的材料确认。

一个很小的测试就有用：找一张只有四五个框和几根箭头的图，转换后改一个标签、移动一个框，再重新导出。这样能看出所谓可编辑到底是保住了结构，还是只把背景图放进一个编辑器。不要等整页复杂算法图做完，才第一次打开输出文件。

## Edit Banana 那张截图，把版本差别写在了页面上

![回复第 197 楼的 Edit Banana 说明页，介绍将图片或 PDF 转为 DrawIO 或 PPTX，并提示 GitHub 版本落后于网页服务](/personal-site/media/posts/research-library-02.png)

_来源：[原帖 #197 楼](https://linux.do/t/topic/1417107/197)。图中的版本提示与前一楼的本地复现困惑相对应。_

页面写了上传图片或 PDF、取得可编辑 DrawIO 或 PPTX 的方向，也直接提示仓库版本与网页不同。这个细节解释了 [#195 楼](https://linux.do/t/topic/1417107/195) 为什么会觉得“同一个工具，本地却不一样”。

保存这类资料时，不妨同时记下用的是在线服务还是本地版本、测试日期，以及拿到的文件类型。现在打开 [Edit Banana](https://editbanana.anxin6.cn/) 看到新界面，也不能把旧截图里的承诺直接当成当前行为。

另一个常见问题是，标签改动后箭头还在原处。文字能编辑，不代表关系已经保住；论文框架图最终仍要按正文逐条看连接方向和术语。检查一根箭头是否代表“输入”还是“反馈”，往往比换配色重要。

## 一站式编辑器的价值，要看材料能不能带走

[#234 楼](https://linux.do/t/topic/1417107/234) 引用了一个论文搜索、精读、写作的一站式项目，配图里能看到 PaperSpark 的编辑界面。

![PaperSpark 编辑器示例，左侧为章节目录，中间为测试文稿，右侧为知识库，上方提供 Markdown 与 TeX 导出](/personal-site/media/posts/research-library-03.png)

_来源：[原帖 #234 楼](https://linux.do/t/topic/1417107/234) 引用的项目截图。文稿明确标注为 mock data，是演示材料。_

对我来说，这张图最值得看的不是中间排得像论文的正文，而是顶部“导出 MD”“导出 TeX”和右侧知识库。假如阅读笔记、引用和文稿只能留在同一个网页里，后面换编辑器会很费劲。能否导出到自己现有的目录，才影响它能不能进入长期工作。

原帖还列了 [Zotero + Obsidian 的写作讨论](https://linux.do/t/topic/1771234)，两者可以放在一起看：一边是集成界面，一边是把文献与笔记放回自己的文件。选择前先试导出一个有标题、公式、引用和图片的小段落，打开后看内容是否还齐，不要只确认出现了一个下载按钮。

## 链接打不开时，先分清失效还是没权限

原帖主文提醒，一些链接属于需要主动加入的科研版块。[#292 楼](https://linux.do/t/topic/1417107/292) 也有人问，为什么点进去显示找不到。因此，“找不到”不必然意味着帖子被删了，可能只是当前账号看不到。

另一个情况是确实过时。[#276 楼](https://linux.do/t/topic/1417107/276) 有人反馈一条写作资源打不开，建议从目录移除。这说明长期汇总也会积累坏链接。保存了标题以后，可以回到作者主页或官方仓库寻找入口；找不到时就标明待核验，不靠旧简介猜剩下的内容。

下次从这份索引拿资料，我只想确认四件事：它解决眼前哪一步；入口能否访问、是否需要权限；能留下什么文件；用一份小材料试完后，哪里仍要人工修改。答案齐了，再把它放进常用目录。不是每个资源都要变成日常工具，保留少数真正能接上工作的小入口就够了。
