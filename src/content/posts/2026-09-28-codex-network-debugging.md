这不是一篇“Codex 必须永远开 TUN”的配置教程。我的原始记录只证明了一件更具体的事：在当时那台机器上，Codex 的启动函数把代理环境删掉了，所以终端里的请求没有走和其他应用相同的链路。

这件事值得写下来，是因为修复前后出现了两个不同的错误。第一阶段是请求根本没有按预期离开本机；第二阶段网络恢复后，服务端又返回了 provider 鉴权不可用。错误变了，说明排查已经进入下一层，而不是“还是网络不通”。

## 先还原当天的时间线

| 时间线上的现象 | 我当时验证的假设 | 得到的证据 | 下一步 |
| --- | --- | --- | --- |
| 浏览器和其他应用正常，Codex 失败 | 整台机器断网 | 不成立，问题集中在启动方式 | 对比终端和应用的进程环境 |
| 直接运行 Codex 仍失败 | 节点或账号坏了 | 还不能下结论，进程可能没拿到代理 | 查看当前 shell 与启动函数的环境差异 |
| 读 `.zshrc` 里的 `codex()` 函数 | 函数可能在“清理”变量时误伤代理 | `-u` 把代理变量一起删掉 | 只修改启动入口，保留原有网络链路 |
| 修复后不再是原来的连接错误 | 网络链路已经恢复 | 服务端返回 `503 auth_unavailable` 类错误 | 转去检查 provider、额度和模型权限 |

原记录里的关键不是某个端口数字，而是这条因果关系：**浏览器正常不能证明命令行进程正常；代理客户端显示已连接，也不能证明启动出来的 Codex 继承了代理。**

## 真正的根因：入口做了过度清理

为了让 Codex 使用固定的环境，我曾经在 `.zshrc` 里写了一个包装函数。这个函数的意图是清理旧配置，避免不同代理混在一起；但它用取消设置的方式把所有代理变量都移除了。于是，函数外的 shell 可能仍然有代理，函数内启动的 Codex 却看不到。

当时的链路可以抽象成：

```text
Codex 进程
  └─ 启动函数（错误地清理代理环境）
      └─ 本地代理入口
          └─ 远端节点
              └─ provider
```

修复不是再加一个代理，也不是把所有流量强行改成另一条路，而是让启动入口不再破坏已经存在的环境。改完以后我重新启动进程，观察错误是否发生变化，再决定是否进入下一层。

## 为什么修复后仍然报错

网络恢复后出现的 `auth_unavailable`，说明请求至少已经到达了代理后的服务链路。它可能与 provider 没有可用凭据、模型权限、额度或节点限制有关，但这些都不是“终端没走代理”的同一个问题。

我把它拆成四层，之后遇到类似问题就按层排查：

1. **进程层**：Codex 从哪个 shell、脚本或桌面入口启动？
2. **网络层**：代理变量、系统代理或 TUN 是否真的被这个进程使用？
3. **鉴权层**：请求到达服务端后，账号、provider、额度和模型权限是否有效？
4. **工具层**：模型能否继续访问项目目录、SSH、测试和其他外部工具？

错误码只是线索，不是结论。网络未建立时，优先找启动入口和路由；拿到明确的 `401`、`403`、`429` 或 provider 错误后，就应该停止继续改路由，转去看服务端语义。

## 一次只验证一个假设

我现在会把排障记录写成下面这种小卡片，而不是边猜边改五个配置：

```text
现象：浏览器正常，终端里的 Agent 失败
假设：启动函数没有继承代理
最小验证：比较函数内外的进程环境，不公开具体值
改动：只恢复代理变量继承
新现象：出现 provider 鉴权错误
结论：网络层已推进，下一步不再改 TUN
```

这个格式有两个好处。第一，它把“我觉得是代理”变成别人可以复查的证据链；第二，它保留了错误变化，避免修复一层以后又把新的错误误判成回归。

## 我不会这样做

- 不会因为浏览器正常，就直接重装 Codex 或更换模型。
- 不会同时修改 shell、系统代理、TUN 和 provider 配置；那样即使恢复也不知道根因。
- 不会把真实 API key、内网地址或本机端口复制进排障文章和截图。
- 不会把代理客户端的“已连接”当作业务验收；真正的验收应来自当前进程和目标服务的结果。

最后一点尤其重要：**连接成功只说明链路走通了一段，不说明 provider 一定有可用鉴权。** 这次故障让我保留的不是某个神奇开关，而是“进程环境 → 网络 → 鉴权 → 工具”的分层顺序。

## 来源与范围

本文重写自 2026-07-23 的本地记录，具体配置已经脱敏。它适用于解释排障思路，不足以证明其他系统、代理客户端或模型服务必须使用同样的设置。不同环境请先记录现象，再从启动入口开始验证。
