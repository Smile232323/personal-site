本站使用本地 Sveltia CMS 编辑内容。保存后，macOS 后台同步服务会在短暂防抖后自动提交并推送内容文件。

网络不可用时，变更保留在本地；网络恢复后同步服务会自动重试。公开页面由 GitHub Actions 构建并部署到 GitHub Pages。

## 一篇文章从哪里开始

原始资料先留在本地知识库，博客只接收经过筛选的公开稿。写作时先确认资料的来源和日期，再决定文章要解决的读者问题，最后补上复查条件。这样发布队列里的文章不会只是“我看过某个帖子”，而是有明确的阅读价值。

## 发布前的四次检查

我会依次检查事实和来源、隐私和敏感操作、图片和链接、构建和搜索索引。未来排期的文章保留在仓库里，由定时构建在日期到达后上线。文章发布后再从手机和桌面各打开一次，确认正文宽度、图片和导航都正常。

## 站点也需要维护记录

内容同步、依赖升级和部署失败都写进提交记录，文章本身只保留面向读者的结论。出现问题时，先看最近一次构建和同步状态，再判断是内容错误、配置变化还是网络问题。把站点当作一个长期项目维护，才能让“持续更新”变成实际习惯。
