一次成功演示不能证明 Agent 可靠。更有用的评价维度是：它是否正确理解任务，是否在动手前说明计划，是否保持改动范围，是否主动运行验证，失败后能否回到安全状态。

我会把任务分为读、写、执行和外部操作四类，分别设置权限和验收标准。越接近不可逆动作，越需要人工确认和完整日志。

## 先准备失败样本

评测 Agent 时，我会提前准备缺少关键信息、需求互相冲突、工具返回错误和权限不足的任务。成功样本只能证明它在理想输入下会工作，失败样本才能看出它是否会追问、降级、回滚和停止。

## 评价过程而非口才

记录 Agent 是否先读规则、是否解释计划、是否保持改动范围、是否运行验证以及失败后如何修正。输出很长不等于理解很深，能让人快速定位状态和下一步的系统，才更适合长期使用。
