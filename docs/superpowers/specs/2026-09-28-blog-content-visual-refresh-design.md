# 博客内容与视觉增强设计

## 目标

把现有的资料摘要升级为可以长期阅读和检索的博客内容：主文章补足背景、过程、失败路径和可执行清单，笔记补足上下文与使用边界，每篇公开内容都配有主题视觉或结构图。

## 范围

- 处理 `src/content/posts/` 中的 20 篇主题文章和 `src/content/notes/` 中的 8 篇新增笔记。
- 不修改 `/Users/kaima/Documents/Obsidian Vault/LinuxDo` 原始文件。
- 技术主题使用原创 SVG 结构图，生活与创作主题使用原创 SVG 场景图；图片文件存放在 `public/visuals/`，由 Markdown 正文引用。
- 主文章目标长度为约 1,200–2,000 个中文字符，笔记目标长度为约 600–1,000 个中文字符；长度服从事实密度，不用重复句子填充。

## 内容结构

每篇主文章按“问题背景 → 关键概念 → 实践流程 → 常见失败 → 验收清单 → 个人判断”展开。笔记按“适用场景 → 方法步骤 → 边界与复查时间 → 下一步”展开。来源说明保留原始资料时间、整理时间和来源链接，不公开原始资料里的私人身份信息。

## 视觉系统

文章在正文前展示一张 `figure`，包含图片、简短说明和无障碍 `alt` 文本；流程图和架构图中的文字使用简短中文，避免把不可核验的数字和品牌排名写进图里。公共路径统一使用 `/personal-site/visuals/`，本地开发通过 Astro base 配置自动适配。

## 验收标准

1. 每篇公开文章和笔记都有至少一处图片引用。
2. 主文章正文平均明显长于当前摘要版，且新增内容不是重复改写。
3. 构建、格式检查、ESLint 和 Astro 类型检查通过。
4. 构建产物中图片路径可访问，移动端不出现横向溢出。
5. 敏感信息扫描不出现凭据、私人联系方式、真实内网地址或可直接滥用的操作步骤。
